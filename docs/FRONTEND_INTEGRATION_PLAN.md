- Existing `frontend/src/index.css` is an old **dark-navy theme** → replaced by Stitch tokens.
- Existing scaffold: React 18 + Vite + react-router-dom + lucide-react. Pages: SplashIntro, DashboardPlaceholder, MobileCapturePage.
- **3D hero:** `stitch/three.js.html` has a full working scene (three.js r125, ambient+directional+blue rim lights, PCFSoftShadowMap, procedural `airplane` Group). Port to a React component; later swap to `.glb`.
- Backend (9 endpoints, verified): `POST /api/inspections/{id}/images` (upload→YOLO→AeroMemory, atomic), `GET /api/inspections/{id}/latest-result` (2s polling), `POST|GET /api/inspections`, `POST /api/decisions/{detection_id}`, `POST /api/detect`, `GET /api/metrics` (NEW — serves logs/eval + logs/latency + models/registry verbatim), `GET /health`, `GET /`.
- `GET /api/metrics` paths resolve relative to `backend/app/api/metrics.py` (parents[3] = repo root) so uvicorn works from any cwd. Frontend consumes it via `api.getMetrics()` (typed `ModelMetrics`); Landing + ModelPerformance are LIVE from it (no more hardcoded eval numbers).
- **Shape facts (mock↔real mismatches):** bbox is `{x,y,width,height}` (NOT x1y1x2y2); upload form field is `file` (NOT `image`); `/health` returns `{status, database}`; **no `/api/metrics` endpoint exists yet** (numbers live in `logs/eval_*.json` + `logs/latency_*.json`).
- Enum strings (display exactly): aeroMemory states `new|stable|increased|decreased|resolved`; tracked status `New|Monitored|Progressing|Repaired|Closed`; severity `Low|Medium|High|Critical`; classes by ID `0 crack, 1 corrosion, 2 dent, 3 missing_fastener`.
- **inspection.status is ALWAYS `"completed"`** — set at creation (`inspection.py`); the upload pipeline never flips it (verified in `inspection_image.py`). So "pending/awaiting images" rows never occur with the current backend; History's pending branch is future-proofing only. AeroMemory `latest-result` returns `has_result:false` + message when an inspection has no images yet (per-screen empty state, not the status field).
- AeroMemory engine (repo `aeromemory/` package, wired in `inspection_image.py`): on upload it fetches the previous inspection for the same aircraft+component, image-registers previous boxes onto the new frame, matches, then per matched defect evaluates progression state + re-assesses severity; unmatched detections become NEW tracked defects (DEF-#### ids). `latest-result` returns the CURRENT tracked set via `get_active_defects` (includes defects not re-detected in the latest image).
- DB bootstrap for local testing: `DATABASE_URL="sqlite:///./aerointel_test.db"`, `PYTHONPATH=backend python -m app.db.init_db`, then `uvicorn app.main:app` from `backend/`.
- Stitch screens copied to `stitch/` (20 HTML files): landing, in_app_dashboard, new_inspection (capture/photo_preview/processing), inspection_result, inspection_history (+empty state), inspection_report, aeromemory (historical_comparison, ghosted_overlay), reports (+empty state), model_performance, settings_configuration, mobile (capture/photo_preview/processing/result), three.js. `aerointel_precision_ui` had **no code.html** (PNG-only reference, not copied); `close_up_high_resolution…` is a photo asset folder, not a screen.
